# Day 7 — AHB Basic Transfers and Wait States

**Date:** 17 October 2026

## What I studied
Continued studying AHB basic transfers, focusing on the relationship between the address and data phases and how HREADY is used to extend a transfer with wait states.

## What I understood
- An AHB transfer is divided into an address phase and a data phase.
- The address phase normally lasts one HCLK cycle, while the data phase can be extended using wait states.
- Address/control information for one transfer can overlap with the data phase of the previous transfer because AHB uses pipelining.
- Each data transfer is associated with its corresponding address and control information.
- HWRITE indicates whether the transfer is a read or write.
- HREADY determines whether the current transfer can complete.
- When HREADY is LOW, the transfer is extended and the manager must wait.
- When HREADY returns HIGH, the transfer can complete and the bus can progress.
- During an extended write transfer, the write data must remain stable.
- For a read transfer, the subordinate only needs to provide valid read data when the transfer is completing.

## Key takeaway
The most important idea from today's session was that AHB pipelines the address and data phases, but a transfer cannot complete while HREADY is LOW. Wait states therefore extend the data phase while the required transfer information remains valid until completion.
