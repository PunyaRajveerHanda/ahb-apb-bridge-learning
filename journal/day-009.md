## What I understood

### Burst types

HBURST identifies the burst type and, for fixed-length bursts, the number of transfers.

| HBURST[2:0] | Type | Description |
| --- | --- | --- |
| 000 | SINGLE | Single transfer |
| 001 | INCR | Undefined-length incrementing burst |
| 010 | WRAP4 | Four-beat wrapping burst |
| 011 | INCR4 | Four-beat incrementing burst |
| 100 | WRAP8 | Eight-beat wrapping burst |
| 101 | INCR8 | Eight-beat incrementing burst |
| 110 | WRAP16 | Sixteen-beat wrapping burst |
| 111 | INCR16 | Sixteen-beat incrementing burst |

HSIZE determines the number of bytes transferred per beat:

`Bytes per beat = 2^HSIZE`

For a 32-bit data bus, the supported transfer sizes are byte, halfword and word.

### Incrementing bursts

Each successive address increases by the transfer size.

For an INCR4 burst of word transfers starting at `0x38`:

`0x38 → 0x3C → 0x40 → 0x44`

An incrementing burst must not cross a 1 KB address boundary.

### Wrapping bursts

A wrapping burst remains within an aligned address block.

`Wrap-block size = Bytes per beat × Number of beats`

For WRAP4 word transfers, the block size is 16 bytes. Starting at `0x38`, the addresses are:

`0x38 → 0x3C → 0x30 → 0x34`

The address wraps to the beginning of the block, which is not necessarily the burst’s starting address.

I also worked through byte-transfer examples:

- Starting at `0x02`: `0x02 → 0x03 → 0x00 → 0x01`
- Starting at `0x0F`: `0x0F → 0x0C → 0x0D → 0x0E`

For WRAP4 halfword transfers, the block size is eight bytes. One example is:

`0x00 → 0x02 → 0x04 → 0x06`

### Transfer alignment

Alignment depends on the transfer size:

- Byte transfers can start at any byte address, including odd addresses.
- Halfword transfers require addresses divisible by two.
- Word transfers require addresses divisible by four.

### Burst timing and wait states

Reviewed timing diagrams showing how burst addresses and their corresponding data phases overlap.

- The first beat uses NONSEQ; subsequent transfer beats use SEQ.
- HREADY LOW extends the current transfer.
- Write data must remain stable during the extended data phase.
- Wait states increase the transfer duration without adding burst beats.

## Key takeaway

Incrementing bursts continue through successive addresses, while wrapping bursts remain within an aligned block. Correct address calculations require both the transfer size and the burst length.
